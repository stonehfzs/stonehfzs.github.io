## 0. 背景

最近对个人小服务器上部署的Overleaf社区版进行了版本更新。由于最初是直接通过 `git clone` 官方仓库并手动编写 `docker-compose.yml` 部署的，版本已经落后太多（3.x/4.x）。在尝试直接升级到最新版（6.x）的过程中，踩遍了 MongoDB 版本不兼容、二进制文件存储格式变更、Docker Compose 语法升级等所有的坑。

所以最好还是直接从Overleaf Toolkit开始部署，这样可以省去很多麻烦。但是假如已经用原来的版本部署了，那么下面的方法应该能够解决迁移中其他辅助容器兼容的问题。

---

## 1. 数据迁移与环境准备

在服务器上操作，核心一定是数据备份。我们需要将旧的 Docker 数据平滑过渡到 Toolkit 的管理线下。

### 数据目录对接

Toolkit 初始化后会生成一个 `data` 目录。我们要把旧的数据手动复制进去。

**旧路径**：`~/sharelatex_data` (应用数据), `~/mongo_data` (数据库), `~/redis_data` (缓存)

**新路径**：Toolkit 目录下的 `data/overleaf`, `data/mongo`, `data/redis`

**复制文件**：

```bash
sudo cp -a ~/sharelatex_data/. ./data/overleaf/
sudo cp -a ~/mongo_data/. ./data/mongo/
sudo cp -a ~/redis_data/. ./data/redis/
```

## 2. MongoDB 的升级

这是最核心的坑：MongoDB **不支持跨大版本直接升级数据文件**。比如你直接从 4.4 升到 7.0，数据库会因为不认识旧格式直接崩溃（报错代码 62）。

**操作逻辑**：先换镜像，启动后执行“版本确认”命令（FCV），让数据库把数据文件标记为新版，再换更高版本的镜像。

### 1. 升级到 6.0

```bash
# 1. 修改 config/overleaf.rc 里的 MONGO_VERSION=6.0
echo "MONGO_VERSION=6.0" >> config/overleaf.rc

# 2. 重启容器
./bin/stop
./bin/up -d

# 3. 执行确认命令（FCV）
docker exec -it mongo mongosh --eval 'db.adminCommand({setFeatureCompatibilityVersion: "6.0"})'
```

### 2. 升级到 7.0（稳定版）

```bash
# 1. 修改 config/overleaf.rc 里的 MONGO_VERSION=7.0
echo "MONGO_VERSION=7.0" >> config/overleaf.rc

# 2. 重启容器
./bin/stop
./bin/up -d

# 3. 执行确认命令（FCV，注意必须加 confirm: true）
docker exec -it mongo mongosh --eval 'db.adminCommand({setFeatureCompatibilityVersion: "7.0", confirm: true})'
```

最后的输出显示 `{ok: 1}`表示成功。

## 3. 深度清理冗余 Docker 镜像

在频繁切换 4.4、6.0、7.0、8.0 镜像的过程中，你的服务器会产生大量废弃镜像。每个镜像都有 1GB 左右，不清理会迅速撑满磁盘。

```bash
# 1. 自动清理：删除所有未被当前容器使用的镜像（清理效果最强）
docker image prune -a -f

# 2. 手动清理：如果有些旧镜像依然存在，指定删除
docker rmi mongo:4.4 mongo:6.0 mongo:8.0
docker rmi sharelatex/sharelatex:5.1.1 sharelatex/sharelatex:6.0.1
```

这里需要保证当前的 5.5.7 和 Mongo 7.0 正在运行（Up）再执行清理，否则正在用的镜像也会被删掉。

## 4. 用Toolkit部署Overleaf 5.5.7

### 修改版本号

在 Toolkit 中，镜像名和版本号是分开的。`overleaf.rc` 里只写镜像名 `sharelatex/sharelatex`。版本号在 `config/version` 文件里修改：

```bash
echo "5.5.7" > config/version
```

### 文件搬运

从旧版 Overleaf 升级时，附件存储方式发生了变化，必须手动执行迁移脚本，否则项目里的图片、PDF 都会找不到：

```bash
# 必须在 5.5.7 容器运行状态下执行
docker exec -it sharelatex node services/web/scripts/binary_files_migration.js
```

### 重启容器并确认状态

```bash
# 1. 重启容器
./bin/stop
./bin/up -d

# 2. 确认 sharelatex 和 mongo 都是 Up 状态
docker ps -a
```

## 5. 重建TeX Live环境

新更新完的 Overleaf 一般是默认没有texlive环境支持的，这也是官方推荐的做法。我们需要在容器里面重新创建新的texlive环境。

```bash
# 1. 先更新tlmgr
docker exec -it sharelatex tlmgr update --self
# 2. 换清华源
docker exec -it sharelatex tlmgr option repository https://mirrors.tuna.tsinghua.edu.cn/CTAN/systems/texlive/tlnet
# 3. 安装完整的texlive环境
docker exec -it sharelatex tlmgr install scheme-full
```
